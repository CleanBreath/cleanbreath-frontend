# 다국어 지원 (ko / en / ja) 설계

## 왜

한국에 사는 일본인·영어권 흡연자와 관광객이 "여기서 피워도 되나?", "가까운 흡연구역이 어디지?"를 바로 알 수 있게 한다. 곧 일본 구역 데이터가 들어올 예정이라 일본어 검색 노출도 목표다.

## 목표

- 화면 글자 전체를 한국어·영어·일본어로 제공한다: 버튼, 범례, 안내 문구, 오류 메시지, 법령·소개·개인정보·등록·게시판·상태 페이지, 메타데이터(title/description/OG/JSON-LD).
- 첫 방문 언어는 **브라우저 언어 설정(Accept-Language)** 으로 고른다. 접속 국가(IP)는 쓰지 않는다. 서울에 온 일본인 관광객도 일본어를 봐야 하기 때문이다.
- 화면에 언어 전환 버튼을 두고, 고른 언어는 쿠키로 기억해 다음 방문에도 유지한다.
- 언어별 URL: 한국어는 기존 주소 그대로(`/`, `/statute` …), 영어는 `/en/...`, 일본어는 `/ja/...`. 기존 한국어 URL과 SEO는 깨지지 않아야 한다.
- 언어별 canonical, `hreflang`(ko/en/ja/x-default=ko) alternates, sitemap alternates, `<html lang>`.

## 비목표

- 구역 데이터 번역. 구역 이름(`buildingName`), 주소(`addressName`), 게시판 글, 지역명은 백엔드 원문 그대로 보여 준다. 원문이 택시 기사에게 보여 주거나 지도 앱에 붙여 넣기 좋다. 정해진 값(`category`: SMOKING/NON_SMOKING 등)만 화면에서 번역한다.
- 일본 데이터 지원(일본 법령 안내, 지도 초기 위치, 나라별 규칙). 다음 작업이다. 다만 이번 구조가 그 작업을 막지 않아야 한다(예: 문구에 "한국"을 불필요하게 박지 않는다).
- 백엔드 변경.

## 반대 목표 (동작해도 실패인 경우)

- 기존 한국어 URL이 바뀌거나 리다이렉트돼 검색 순위를 잃는 것.
- 검색 로봇(Accept-Language 없음)이 `/`에서 다른 언어로 리다이렉트되는 것.
- 영어·일본어 화면에 한국어 UI 문구가 섞여 남는 것(원문 데이터 제외).
- 백엔드가 주는 한국어 오류 메시지(`{ message }`)가 영어·일본어 화면에 그대로 뜨는 것.
- 어색한 기계 번역. 일본어는 일본인이 쓰는 표현(喫煙所, 禁煙エリア/禁煙区域, 過料 등), 영어는 자연스러운 표현(smoking area, no-smoking zone, fine)을 쓴다.

## 정해진 방식

- **라이브러리:** `next-intl` (Next.js 16 App Router, `proxy.ts`). (구현자 판단: 직접 구현보다 라우팅·감지·포맷이 검증돼 있음)
- **라우팅:** `app/[locale]/...`, `localePrefix: 'as-needed'`, `defaultLocale: 'ko'`, `localeDetection: true`(Accept-Language + `NEXT_LOCALE` 쿠키).
- **메시지 파일:** `messages/{ko,en,ja}/<namespace>.json`. 네임스페이스로 나눠 병렬 작업 충돌을 피한다.
- **법령 JSON(`src/json/statute*.json`):** 언어별 파일로 둔다.
- **법률 문서:** 개인정보처리방침과 법령 안내는 영어·일본어 번역본에 "참고용 번역이며 한국어본이 우선한다" 고지를 단다. (구현자 판단)
- **개발자 실명(`/about`):** 한글 이름 그대로 둔다. (구현자 판단)
- **네이버 지도 라벨 언어:** Maps JS API v3가 언어 파라미터를 지원하면 화면 언어에 맞춘다. 지원하지 않으면 그대로 둔다.

## 구현자에게 맡기는 것

- 언어 전환 버튼 위치와 모양(기존 디자인 시스템 `design-system/cleanbreath/MASTER.md` 따름).
- 네임스페이스 키 이름.
- 날짜·숫자 포맷 방식.
